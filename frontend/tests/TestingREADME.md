# CyberComply Frontend Tests

Unit tests for the CyberComply frontend logic using **Jest** and **jsdom**.

---

## Prerequisites

Make sure **Node.js** is installed on your machine.

```bash
node --version
npm --version
```

If either command fails, download and install Node.js from **https://nodejs.org/en/download** (click the 'Windows Installer (.msi)' button towards bottom left corner).

Once the .msi file is downloaded, just click 'Next' through everything — all default options are fine. (Ensure 'Add to Path' option is enabled - it should be enabled by default)

Once installation successfully completes, restart VS Code and type the version commands given above and check if it has been installed successfully.

---

## Setup

Navigate to the `frontend` folder and install dependencies:

```bash
cd frontend
npm install
```

This installs Jest and all required packages listed in `package.json`. You only need to do this once.

---

## Running the Tests

From the `frontend` folder, run:

```bash
npm test
```

This runs all test files inside `tests/unit/` and prints a pass/fail result for each test case.

To run a specific test file only, use a similar command as shown below:

```bash
npx jest tests/unit/home.test.js --verbose
npx jest tests/unit/report_viewing.test.js --verbose
```

## What is Being Tested

These are **unit tests** — they test pure JavaScript logic functions extracted from the frontend HTML files in isolation, without needing a browser, a running server, or any external API.

| Test File | HTML File | What It Tests |
|---|---|---|
| `home.test.js` | `home.html` | Organisation name validation, Analyse button gate logic |
| `compliance.test.js` | `compliance.html` | Gap filtering, risk filtering, severity sorting, risk counts |
| `recommendations.test.js` | `recommendations.html` | PDPA reference builder, legal text rephraser, action step deriver |
| `report_viewing.test.js` | `report_viewing.html` | Top recommendation derivation, compliance detail sorting |

## How to Write a New Test File

1. Create a new file inside `tests/unit/` named `<pagename>.test.js`
2. At the top, require Jest globals:

```js
const { describe, test, expect } = require('@jest/globals');
```

3. Copy the pure JavaScript function(s) you want to test directly from the relevant HTML file's `<script>` block into the test file
4. Write your tests using `describe` and `test` blocks:

```js
describe('myFunction', () => {
    test('does something expected', () => {
        const result = myFunction('input');
        expect(result).toBe('expected output');
    });

    test('handles edge case', () => {
        const result = myFunction('');
        expect(result).toBe(false);
    });
});
```

5. Run `npm test` to verify

---

## Important Notes

- **Do not use `import` statements** — use `require()` instead. The project uses CommonJS (`"type": "commonjs"` in `package.json`), so `import` syntax will cause a parse error.
- Tests do **not** require the Django backend to be running — they test frontend logic only.
- The `node_modules` folder is auto-generated by `npm install` and should **not** be committed to Git. It is already listed in `.gitignore`.
